# CLAUDE.md – rules for agents working on the Terrys.cz e-shop

Terrys.cz is a premium Czech butcher shop and steak e-shop. This repo is the new e-shop: one
Next.js (App Router) application with Payload CMS 3 embedded, PostgreSQL database, Tailwind CSS for
the storefront. The code is maintained by one person who is a marketer, not a full-time developer:
prefer boring, conventional, well-documented solutions over clever ones, and explain non-obvious
things in comments.

## Stack

- Next.js 16 (App Router, Turbopack), React 19, TypeScript (strict).
- Payload CMS 3 (`payload`, `@payloadcms/next`, `@payloadcms/db-postgres`), admin at `/admin`.
  No Payload e-commerce plugin, no Stripe or any other online payment.
- PostgreSQL 16 (local: `docker compose up -d`, CI: GitHub Actions service container).
- Tailwind CSS v4 (CSS-first config in `src/app/(frontend)/globals.css`, brand tokens in `@theme`).
- pnpm via Corepack (version pinned in `package.json` → `packageManager`). Node 24 LTS (`.nvmrc`);
  Payload requires Node `^22.23.5 || ^24.22.3 || >=26.13.1`.
- ESLint (flat config, `eslint-config-next`), Prettier, Vitest (unit), Playwright (e2e).
- Keep Payload packages on the exact same version, and Next.js within the range Payload's
  `@payloadcms/next` declares as a peer dependency. Check official docs before upgrading.

`AGENTS.md` is generated and re-added by `next dev` (Next.js agent rules); keep it committed and
read it: the bundled Next.js docs in `node_modules/next/dist/docs/` match the installed version.

## Layout and conventions

- `src/app/(frontend)` – storefront. Has its own root layout with `<html lang="cs">`.
- `src/app/(payload)` – Payload admin + REST/GraphQL API. Files there are generated by Payload;
  do not edit them (except `custom.scss` for admin styling).
- `src/collections` – one file per Payload collection. `src/payload.config.ts` – Payload config.
- `src/lib` – plain helper functions; unit tests sit next to them as `*.test.ts`.
- `tests/e2e` – Playwright tests (`*.e2e.spec.ts`).
- Code, identifiers and code comments in **English**. All customer-facing text and all admin labels
  (collection labels, field labels, descriptions) in **Czech**.
- After changing collections/fields: run `pnpm generate:types` (commit `src/payload-types.ts`) and
  create a migration `pnpm payload migrate:create <short-name>` (commit `src/migrations/*`).
  `pnpm dev` uses Payload's automatic schema push; CI and production use migrations
  (`prodMigrations` in `payload.config.ts` runs them when the production server starts).
  Never edit a migration that is already merged; add a new one.
- After adding custom admin components: run `pnpm generate:importmap`.
- Admin language: `i18n.supportedLanguages = { cs, en }`, `fallbackLanguage: 'cs'`. The browser
  language decides (English browser → English admin, everything else → Czech).
- Media uploads are stored on local disk in `/media` (git-ignored). `alt` text is required.
- Money: amounts in whole CZK for display via `formatCzk` in `src/lib/format.ts`.

## Business rules – never violate these

1. **No discounts and no discount codes.** No coupon fields, no "sale" prices, no percentage-off
   logic. The single future exception is the Valentine's **Wagyu Burger 1+1** promotion; implement
   it only as that specific, explicitly scoped exception when a stage asks for it.
2. **No free shipping, ever.** Delivery costs a flat **229 Kč** regardless of order value. Personal
   pickup is free. No "free shipping above X" thresholds or banners.
3. **No online payment.** Customers pay on delivery/pickup. No payment gateway, no card forms.
4. **Prices are per kg; final price follows actual weight.** The butcher weighs every order and the
   final price is based on the real weight (typically about ±15 % from the estimate). The storefront
   always shows an **estimated** price together with a notice explaining this. Never present an
   estimate as a final price.
5. **Czech only.** The storefront is in Czech; no language switcher, no other locales.
6. **VAT rate is a per-product setting** (food is 12 %). Never hard-code a single VAT rate globally.
7. **No exit-intent pop-ups** (or similar interruptive pop-ups).
8. **No unlicensed fonts.** Use system fonts or fonts whose licence permits web use; self-host them.

## Workflow

- One stage = one branch named `etapa-N-nazev` (e.g. `etapa-1-katalog`). Do not push or merge
  without the owner's approval.
- A stage is done only when `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm build` pass, and
  `pnpm test:e2e` passes with the database running. CI (`.github/workflows/ci.yml`) runs all of these.
- Secrets live only in `.env` (git-ignored). Document every new variable in `.env.example` with a
  comment. Never commit real secrets, API keys or passwords.
- Keep `README.md` (Czech, for a non-developer) up to date when scripts, setup or structure change.

## Local environment notes

- Local Postgres from `docker-compose.yml`: user/password/db `terrys`. Host port is configurable
  with `POSTGRES_PORT` in `.env` (default 5432; on the owner's machine 5432 is used by another
  project, so the local `.env` uses 5433).
- Do not run `pnpm start` (which applies migrations) against the dev database that `pnpm dev`
  pushed schema into; use a separate empty database for that.
